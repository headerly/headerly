# Compatibility and limits

## Browser requirement

Headerly declares Chrome 145 as its minimum Chrome version. This is required for DNR top-level-domain conditions. Compatible Chromium-based browsers must implement the same APIs used by a configured profile.

## Tab and tab-group selections

Selections saved under **Tab IDs** and **Tab groups** are cleared when the browser restarts. Chrome only guarantees [tab IDs](https://developer.chrome.com/docs/extensions/reference/api/tabs#property-Tab-id) and [tab-group IDs](https://developer.chrome.com/docs/extensions/reference/api/tabGroups#property-TabGroup-id) within the current browser session. This is a browser limitation, not a Headerly limitation.

Headerly automatically pauses any profile that had an active tab or tab-group condition before the restart. This prevents the profile from unexpectedly applying to more tabs after its saved selection is cleared.

## Network-stack boundaries

DNR applies to requests that reach Chrome's network stack. It may not affect responses generated by a Service Worker's fetch handler or returned from CacheStorage, although network requests made by the Service Worker can still be affected.

## DevTools response-header display

In affected Chromium versions, the Network panel can display the original response headers instead of changes applied by DNR. This behavior is tracked in [Chromium issue 40196848](https://issues.chromium.org/issues/40196848).

Use a same-origin `fetch()` in the Console to inspect the headers exposed to the page. See [Modify response headers](/guides/modify-response-headers#verify-the-modified-header) for the verification procedure and its CORS constraints.

## Header restrictions

Chrome restricts which request headers can use `append` and how lower-priority rules may modify a header after `set`, `append`, or `remove`.

Limits can change between browser releases. Treat Chrome's [Declarative Net Request documentation](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest) as authoritative.
